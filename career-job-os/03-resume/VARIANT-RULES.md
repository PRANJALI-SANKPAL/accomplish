# Variant rules — emphasis only

## Allowed when tailoring to a JD

1. Reorder bullets so the most JD-relevant true work is first.
2. Use JD synonyms for the **same** work (e.g., “REST services” ↔ “REST APIs”).
3. Move a true secondary skill into Skills if JD emphasizes it (e.g., React) — only if interviewable.
4. Tilt summary toward backend / full-stack / data — without new domains.
5. Add 1–2 JD keywords that already match true experience.

## Forbidden when tailoring

1. Changing primary language identity (Java/Python ↔ Go).
2. Adding fraud, zero-trust, DNS/TCP, Oracle, GraphQL, DynamoDB unless in Master Truth.
3. Inflating scale numbers.
4. Changing dates/titles/companies.
5. “Ready to contribute to [Company mission]…” AI closers.
6. Creating a second conflicting PDF that contradicts LinkedIn.

## Fit threshold

- Fit ≥ 70%: create emphasis variant + apply/refer
- Fit 40–69%: apply only if referral + honest gaps noted
- Fit < 40%: do not apply; log as skipped with reason
